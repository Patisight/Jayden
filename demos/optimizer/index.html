01

它解决什么问题/ The Loop

人工调天线的时间，一半花在「改一个数、等一次求解、看一眼曲线」上。

贴片天线的回波损耗、增益、效率、端口隔离互相掣肘：手工调参是在这条权衡面上凭经验打转， 每转一次都要付出一整次全波仿真的时间。这套工具把 HFSS 从「人操作的软件」变成「程序调用的求解器」， 让算法接替打转。

  • 参数写入 —— 脚本向 HFSS 写入命名变量，几何随之更新
  • 求解 —— 调用求解并确认本轮真实算完
  • 取值 —— 读取 S 参数、远场增益与效率（无远场球面时自动创建）
  • 评估 —— 目标公式解析为指标向量，判定是否达标
  • 并行执行 —— 每个工程副本一个独立 HFSS 进程，worker 崩溃自动重启并重派任务；500 次求解的墙钟时间按实例数成倍压缩
  • 全程留痕 —— 每次评估追加写入 JSON Lines，最终非支配解与配置快照按算法 / 时间戳归档，即「结果分析」面板里的每个条目

02

六个面板分别对应什么/ Panels & Endpoints

左侧导航不是一般意义上的「页面切换」，它按的就是优化任务的配置顺序。

六个面板共用同一份 /api/config 配置文档，左侧导航按的就是优化任务的配置顺序； 「保存配置」落盘后由命令行 run.py 读取执行——Web 界面只是编辑器，跑任务的从来不是它。

01 项目配置
GET /api/templates · GET /api/browse · GET|POST /api/config模板卡 + .aedt 路径 + 设计/设置/扫频名 + 并行路径表
02 优化变量
POST /api/config → variables[]{name, bounds[2], unit}边界可填公式引用其它变量，由约束求解器按依赖序展开
03 优化目标
POST /api/config → objectives[]{name, formula, freq|freq_range, goal, target, weight}方向只有最小化 / 最大化两种，权重用于标量化路径
04 算法配置
GET /api/algorithms单选算法 + 详情描述（全称 / 适用目标数 / 优势 / 局限 / 最佳场景）+ 专有参数面板
05 运行控制
POST /api/start · POST /api/stop · GET /api/status（1 s 轮询）进度条 = progress / total，日志滑窗 50 行，错误可展开 traceback
06 结果分析
GET /api/results · GET /api/results/{name}历史运行目录列表 → 非支配解卡片：参数 + 各目标 actual_value

两处面板耦合值得一提：算法配置的专有参数随算法切换（选 MOPSO 出现惯性权重与学习因子， 选 CMA-ES 只剩初始步长），只有对应算法才会消费；优化变量的边界支持公式， 结构对称、避免干涉这类几何约束能直接写进取值范围，避免优化器把求解次数浪费在物理上不成立的几何上。

03

为什么要多目标算法与代理模型/ Algorithms & Surrogates

一次求解要几分钟，一次任务要几百次——这两句话决定了整套算法选型。

加权求和不能替代多目标算法：换一次权重就要从头再跑几百次仿真，且非凸前沿上的解根本取不到。 多目标算法一次运行直接交付一整条 Pareto 前沿——工程师拿到的是「这套尺寸换那 0.3 dB 增益值不值」的完整菜单， 而不是一个答案。

七个算法各有分工：目标数 ≤3 时自实现的 MOPSO / NSGA-II 是快而稳的基线； 目标更多、前沿形状更复杂时，由 pymoo 接入的 NSGA-III、RVEA 等以参考点或角度距离引导搜索。 界面上每个解都带 is_predicted 标记，预测点与真仿真点分开记账、分色呈现； 前沿上要用于样机的尺寸，仍应送回 HFSS 复算确认。

早停
达标即停：非支配解已满足全部目标时，剩余仿真预算不再有意义，算法每代检查并提前终止。 所以演示里那次合成任务的进度条不会走满，通常在五到八成之间停住。

代理模型

用已仿真过的点训练廉价预测器（高斯过程），优化器先在预测面上大面积搜索， 只把最有希望的少数候选送进 HFSS 做真仿真，真值再回填训练集—— 仿真次数从预算里被成倍买回。

可选算法（与源码注册表一致）

MOPSO
2–3 目标自实现 · 收敛最快
NSGA-II
2–3 目标自实现 · 稳健基线
CMA-ES
1 目标自实现 · 加权和 · 变量耦合
AGE-MOEA2

04

这份演示的边界/ What Is Real

界面与接口契约是真的，全部数值为合成。

真实
界面 与结构

Vue3 + Element Plus 的控制台照搬源项目 web/index.html，面板、字段、校验、轮询节奏、日志措辞都未改动。

真实
契约 与字段

14 个接口的响应结构按 server.py 的路由与 Pydantic 模型对齐：变量用 bounds，目标用 actual_value，列表限 20 条。

合成
全部数值

项目路径、变量边界、目标值、迭代进度、Pareto 解、历史运行记录都是垫片现编的，没有任何一次真实求解。

垫片做的是同源请求拦截：这份 app 文件放回源项目的 web/ 目录即可直接对接真实 FastAPI 服务，不改一行界面代码。 两处刻意与真后端不同（文件浏览改为占位路径、模板列表补齐字段）已在 app 文件顶部注释说明。

要跑真的需要什么

  • 本机 Ansys HFSS 与许可证，及 PyAEDT 可连接的版本hardware
  • 参数化好的 .aedt 工程：待优化尺寸须为命名变量，目标报表可取数
  • pymoo（可选）：AGE-MOEA2 / NSGA-III / MOEA/D / RVEA 走的是它optional
  • python server.py，浏览器打开本机服务端口localhost
